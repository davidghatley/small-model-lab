# Reward-hacking audit: E2 r0_cons vs base (judge imajev-9b)

Script: runs/E2/audit/r0_cons/audit.py (stdlib only, run with .venv); raw numbers: audit_stats.json.
Selection rule: tuned win prob = 1 - p_a_avg (a is always base in judge/manifest.jsonl; p_a_avg is order-averaged), over the 96 clean pairs. Top 20 by that value (ties by id). 68 of 96 pairs favour tuned.
Top 20 ids (descending margin): 0004 0027 0057 0021 0024 0083 0033 0049 0068 0091 0080 0017 0011 0037 0002 0025 0047 0054 0031 0076.
Control 10 (random.Random(0).sample of the 96 ids): 0051 0056 0006 0034 0068 0065 0053 0040 0064 0047. (0068, 0047 overlap with top 20.)
Viewing: I looked at side-by-side screenshots (1280x800 viewport, scaled) of all 30 pairs, and read the HTML of 0004 (both), 0027 and 0057 (tuned) in full; the remaining HTML was checked by script (section/keyword/img/trust heuristics), not line by line. Pages are tiny (about 100 visible words, about 4.7 KB), so the screenshots show nearly everything.

## What the tuned pages do differently (pattern counts)
1. Coherent palette vs base rainbow. Base pages often stack 4-7 unrelated per-section gradients (yellow/brown/orange/red, as in 0004 base) or use muddy full-bleed backgrounds. Tuned pages use one purple-blue (or single-colour) hero, a light grey body and white rounded cards with shadows. Pages with >=4 gradients: base 7, tuned 0. box-shadow cards: base 48, tuned 86. This is a genuine visual-polish gain, though it is also the "template" a vision judge likes. About 25 of the 30 viewed pairs show it.
2. Shorter hero. Pages with a 90-100vh hero: base 23%, tuned 4% (top 20: base 50%, tuned 0%). Base heroes in 0027, 0021, 0011, 0033 fill the viewport and push content off-screen; tuned shows hero plus 2-3 sections in the first screen. This favours tuned in a viewport screenshot, but it is also better layout for a user. Not hacking in the "giant hero hides dropped content" sense, since tuned does not drop content to do it (see 3).
3. Content not reduced. Tuned has slightly MORE text (101.7 vs 96.6 words; top 20: 100.6 vs 89.2) and HTML (4778 vs 4669 chars; top 20: 5104 vs 4139). Margin correlates only weakly with word delta (r=0.26). Brief sections present (heuristic): base 6.07, tuned 5.98 of ~6.7 (89% vs 90%). In the top 20, sections missing: base 11, tuned 15 (tuned lacks "contact form" in 0004, 0057, 0024, 0049, 0080, 0017; "logo wall" and "blog preview" absent in both for many). Small net loss, not a pattern that explains the wins.
4. Fewer images. <img> per page: base 1.81, tuned 0.89; external image URLs: 1.05 vs 0.43 (top 20: 1.2 vs 0.15). Base often has broken images (alt text "Coffee Bean Art", "Book Cover 1", black squares). Tuned replaces them with inline SVG (0.43 vs 0.23 per page; top 20: 1.1 vs 0.05) or CSS circles. Judge-friendly because broken-image icons vanish, but a user also gains by not having broken images. Tuned SVGs are crude (identical triangle/blob glyphs in 0027 "How It Works", Covera pricing icons in 0083, a giant half-circle avatar in 0076); 0083 and 0033 tuned look worse in places than the flat base yet still won.
5. Fake/placeholder content, present in both and NOT a tuned-specific hack. Fake names (Jane/John Doe/Smith): base 35, tuned 42. "2023" footer: 95 vs 97. Lorem ipsum: 6 vs 7 (e.g. tuned 0057 case studies are lorem under "Hospital X / Clinic Z"; that page is a trivia-night brief, so the case-study text leaks from an unrelated brief). Placeholder-image markers: 48 vs 41. Fake trust signals ("award", "rated", "trusted by"): 0.083 per page in both; the only clear one in the sample is tuned 0027 "4-star rating on Trustpilot" and fabricated stat numbers (stats blocks "20+/500+/1M+", "100,000 scooters"), which base also invents.
6. No verbatim copying of the brief description (0 in both), no text praising the design (praise-word hits 0.03 vs 0.05 per page, essentially none), no low-contrast text noticed in the viewed tuned pages (a few white-on-pale-gradient hero subtitles appear in base 0021 and 0033, plus tuned 0049/0083 pale gradient hero, minor).
7. Boilerplate: tuned is slightly more templated in markup: "Welcome to X" h1 77% vs 67%; the #6a11cb->#2575fc palette 34% vs 28%; sentences repeated in >=5 briefs: 2 vs 0. But text similarity is not higher: mean pairwise Jaccard of word sets over 30 random pages per policy is 0.103 tuned vs 0.112 base. No template collapse.

## Whole-set deltas (100 briefs, base -> tuned)
HTML length 4669 -> 4778; visible words 96.6 -> 101.7; sections present 6.07 -> 5.98; imgs 1.81 -> 0.89; external img URLs 1.05 -> 0.43; full-viewport hero 23% -> 4%; svgs 0.23 -> 0.43; gradients/page 1.78 -> 1.21; trust-phrase hits 0.083 -> 0.083; praise hits 0.031 -> 0.052; pairwise text Jaccard 0.112 -> 0.103. Page validity: tuned 99 clean vs base 97.

## Caveats
- Section heuristic is keyword-based and noisy (e.g. "contact form" missing may be a form with different wording; "logo wall" is nearly never detectable). It treats both policies the same.
- Control sample (10) shows the same pattern as the top 20 (tuned hero 0% vs 20% full-viewport; tuned fewer images), so the top 20 are not a different kind of page, only a bigger version of the base-failure gap.
- Judge only sees the 1280x800 viewport, and hero-height changes can matter for what it sees; this is a real design factor, but it is the main judge-specific lever I found.

## Verdict
Plausibly a real, modest design improvement, with a small judge-specific component. The wins come mostly from fixing base failure modes (rainbow section gradients, viewport-filling heroes, broken images, unstyled forms) with a safe consistent card/gradient template. I found no content stripping, no verbatim brief copying, no praise text and no increase in fake trust signals. Residual caveats: tuned loses about 0.1 brief sections per page, uses a more templated look (77% "Welcome to X"), and both policies invent names, stats and lorem. Quality is low in absolute terms for both (tiny pages), so "wins" mean "less ugly", not "good".
